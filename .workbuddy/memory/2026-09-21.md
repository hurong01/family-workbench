# 2026-09-21

## 修复「首页本月家庭开销」与「账单本月总支出」金额不一致

### 根因（两条，都要修）
1. **分页排序不稳定**：`getBills` 的 `getAllExpenses` 用 `orderBy('paidAt','desc')` 分页，`paidAt` 是 `YYYY-MM-DD` 字符串，同一天的多笔记录**并列时排序不确定**，`skip/limit` 跨页会重复或漏掉记录。`login` 的 `sumMonthlyExpenses` 甚至没有 `orderBy`。
2. **云端部署滞后**：旧版 `login` 是 `.limit(20)` 求和（只算最新 20 笔），旧版 `getBills` 拿默认上限。本地已改成完整分页求和，但**云函数未重新部署**时线上仍跑旧逻辑 → 首页金额必然小于账单金额。这是用户实际看到的现象。

### 验证方式
写了临时 Node 脚本模拟 150 笔账目（仅 5 个不同日期，大量并列）、金额各不相同、300 次试验：
- 旧写法 `orderBy(paidAt desc)`：**集合不完整 300/300 次，总金额偏差最大 3212 元**
- 新写法 `orderBy(paidAt desc).orderBy('_id','desc')`：集合不完整 0 次，偏差仅浮点精度 1e-10

脚本是临时产物，验证后已删除。

### 代码改动
- `cloudfunctions/login/index.js`：`sumMonthlyExpenses` 分页加 `orderBy('_id','asc')`（唯一键，保证确定性）
- `cloudfunctions/getBills/index.js`：分页加 `orderBy('_id','desc')` 并列键；**新增返回服务端算好的 `total` 与 `expenseCount`**
- `miniprogram/services/cloud.js`：`getBills` 改为返回 `{expenses, total}`
- `miniprogram/pages/bills/index.js`：改用服务端 `total` 显示，不再前端自行求和 → 首页与账单**共用同一数据源**
- `cloudfunctions/exportBills/index.js`：重写为多行可读版本；导出字段 `note` 改为 `itemName || note`（`saveExpense/updateExpense` 已改用 `itemName`，`note` 不再写入，导致导出备注列恒空）；上限 5000 条并新增 `truncated` 标记；列顺序调整为 日期/月份/分类/具体名称/金额/付款人/票据文件ID
- `miniprogram/pages/profile/index.js`：`onShow` 补 `NO_FAMILY` 处理（原来 `r.family.name` 会抛错白屏）；导出达上限时弹窗提示

所有改动文件均通过 `node --check`。

# 2026-09-22

## 小程序已发布 —— 排查对外入口与邀请链路

用户已上线正式版，询问「从哪看地址 / 如何邀请他人使用」。

### 核心认知
**小程序没有网址**，不存在可外发的 http 链接。对外入口只有：小程序码、分享卡片、微信搜一搜、公众号关联菜单/文章、附近的小程序。

### 官方入口位置（已核实来源）
- 小程序码下载：mp.weixin.qq.com → **设置 → 基本设置 → 小程序码及线下物料下载**（普通小程序码无需开发、永久有效、不限数量、免费）。来源：微信开放社区官方文档「小程序二维码功能介绍与生成方式」。
- 带参数小程序码需通过接口开发，用于渠道追踪。
- 分享到朋友圈：官方要求**页面同时实现 `onShareAppMessage`（允许"发送给朋友"）和 `onShareTimeline`（允许"分享到朋友圈"）**，基础库 2.11.3+、微信 8.0.24+。朋友圈打开进入「单页模式」，限制较多（无登录态、不能跳转、tabBar 不渲染、云开发需开启未登录访问）。来源：微信开放文档 share-timeline。

### 本项目发现的三个缺口（阻断邀请体验）
1. **只有 `pages/family/index` 实现了 `onShareAppMessage`**，其余页面（首页/账单/记账/我的）都没有 → 那些页面右上角「···」里没有「发送给朋友」入口。
2. **全项目没有 `onShareTimeline`** → 完全无法分享到朋友圈。
3. **`pages/onboarding/index` 没有「已加入家庭则跳走」的判断** → 已是成员的家人点开分享卡片，会停在「创建/加入家庭」引导页，体验割裂。
4. 另：`family` 页的分享卡片依赖 `this.data.inviteCode`，管理员未先生成邀请码时分享出去的卡片不带码，对方需手动输码（此前评审中的 P1-5）。

### 邀请的正确姿势
家庭账本是私密的：分享小程序本身只会让对方看到引导页。**真正"邀请一起用"必须由管理员在「家庭」页生成邀请码（6 位、7 天有效），再分享带码卡片。**

### 待用户决定
是否补齐 `onShareTimeline` + 各页分享能力 + onboarding 成员跳转。注意：任何代码改动都会触发新一轮提审。

## 追加：后台显示已发布，微信打开仍是开发版

### 后台实际状态（用户截图核实）
- 线上版本 **1.0.0**：发布时间 2026-09-21 15:02:36（全量）
- 线上版本 **1.0.1**：发布时间 2026-09-22 15:44:03，带绿色标签 **「50% 发布中」** → 即**分阶段（灰度）发布**，非全量

### 官方规则（来源：腾讯客服《小程序分阶段发布功能介绍》 kf.qq.com/touch/wxappfaq/1708293Yzyme170829R3uUfE.html）
1. 分阶段发布：15 天内以开发者自定义比例向微信用户发布更新
2. 15 天内必须全量发布或撤销发布；**逾期未操作，平台在第 15 天自动全量**
3. 可递增调整比例；比例 100% 即提前全量
4. 存在分阶段发布中的版本时，**不可发布新版本、不可回退已全量发布的线上版本**
5. **小程序第一个版本必须选「全量发布」**
6. 灰度按**微信号**维度分配，同一账号结果固定；扩大比例时在已命中基础上扩展
7. 灰度白名单 = 项目成员 + 体验成员 + 手动添加，总数 ≤ 100（来源：juejin 灰度发布实践帖）
8. 验证灰度新版本需**杀掉微信进程后重新打开**——小程序代码包本地缓存，新版本下次冷启动才生效（同上）

### 「打开还是开发版」的根因（按可能性排序）
1. **打开方式**：开发版只来自开发者工具「预览」二维码 /「真机调试」；体验版来自体验版二维码。线上版入口只有：微信搜索小程序名称、最近使用/我的小程序、后台下载的正式版小程序码、好友分享卡片。
2. **微信客户端缓存**：此前扫过开发版/体验版二维码，微信保留版本绑定与代码包缓存 → 需在「发现 → 小程序 → 最近使用」**长按删除该小程序**后重新进入。
3. **50% 灰度未命中**：不在灰度白名单内则只是随机 50%，可能仍看到 1.0.0。

### 建议动作
- 自测无问题则在后台把 1.0.1 提升至 **100%**（提前全量）；否则等 2026-10-07 自动全量
- 验证务必用**未加入开发者/体验成员的微信号**，走「搜索」入口
- 代码侧可选加固：`app.js` 增加 `wx.getUpdateManager()` 主动提示更新（当前 `app.js` 仅 13 行，无此逻辑）

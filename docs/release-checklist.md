# 小程序发布上线清单

面向「璀璨家庭账本」（AppID `wx5fd5bd5259d01a00`）的完整发布流程。按顺序执行，每一项都勾掉之后再进入下一阶段。

> 核心结论先说：**代码写完 ≠ 用户能用**。要让别人用上，必须完成「合规声明 → 部署云资源 → 上传体验版 → 提交审核 → 发布」这五步，缺任何一步都是死路。

---

## 阶段零 · 上线方式选择

发布前先确认你想让谁用上，三种方式的差别很大：

| 方式 | 谁能打开 | 是否需审核 | 适用场景 |
|---|---|---|---|
| **开发版** | 只有开发者本人 | 否 | 自己调试 |
| **体验版** | 你添加的体验成员（上限 15 人） | 否 | 家人试用、验收 |
| **正式版** | 所有微信用户（可搜索、可分享） | **是** | 真正上线 |

如果目标只是「让家人先用上」，配置体验版就够了，可以跳过审核。要「让任意用户都能用」，必须走完审核 + 发布。

- [ ] 明确本次目标是体验版还是正式版

## 阶段一 · 账号与合规准备（最容易卡住的一步）

- [ ] **确认主体类型**：个人 / 企业。企业主体需完成微信认证（¥300/年），可选的类目范围更宽
- [ ] **配置服务类目**：mp.weixin.qq.com → 设置 → 基本设置 → 服务类目，选「工具」下的细分项
- [ ] **确认类目是否需要资质**：记账类工具可能被要求补充资质，个人主体有被驳回的风险，务必先确认
- [ ] **配置《用户隐私保护指引》**：设置 → 服务内容声明 → 用户隐私保护指引
  - 本项目必须声明：**微信用户标识（openid）**、**相册（仅写入）**、**摄像头**
  - 依据：`login` 云函数用 OPENID 识别用户；`expense-add` 的 `wx.chooseMedia` 会访问相册与相机
- [ ] **对齐代码与声明**：`pages/privacy/index` 的文案已存在，必须与后台声明一致，**以后台声明为准**
- [ ] 如涉及隐私接口拦截，在 `app.json` 增加 `"__usePrivacyCheck__": true` 并接入 `wx.onNeedPrivacyRequired` 流程

## 阶段二 · 代码与云端资源自检

### 2.1 必须重新部署的云函数

本地改动不会自动生效。以下函数改动过，**必须重新上传**，否则线上仍跑旧逻辑：

- [ ] `login`（首页金额汇总 —— 本次金额对不上问题的根因）
- [ ] `getBills`（账单金额与分页）
- [ ] `exportBills`（导出字段与分页）
- [ ] `saveExpense`、`updateExpense`（`itemName` 字段）
- [ ] `getFamily`、`manageFamily`、`restoreFamily`（三方共用成员标识，必须同版本）

操作：开发者工具 → `cloudfunctions/<函数名>` 右键 → **上传并部署：云端安装依赖**。

> 每次改完云函数都要重复这一步。忘记部署是本项目出现过的最隐蔽的 bug 来源。

### 2.2 数据库

- [ ] 集合 `users`、`families`、`expenses`、`invites`、`backups` 权限设为 **仅云函数可读写**（客户端不得直接读写）
- [ ] 为 `expenses` 建立联合索引：`familyId` 升序 + `month` 升序 + `paidAt` 降序
- [ ] 检查云端已有数据：确认没有 `month` 字段缺失的历史记录

### 2.3 前端收尾

- [ ] 删除云开发模板残留：`pages/index/`、`pages/example/`、`components/cloudTipModal/`
- [ ] 删除 `miniprogram/images/` 下的演示图（约 1.3MB），保留产品自用图
- [ ] `app.json` 的 `pages` 数组同步移除已删页面
- [ ] `sitemap.json` 改为 `"action": "disallow"` —— 私密账本不应被微信搜索索引
- [ ] `.gitignore` 增加 `project.private.config.json`
- [ ] 重写 `README.md`（当前仍是「云开发 quickstart」原文）
- [ ] 删除或修正 `uploadCloudFunction.sh`（仍是未替换的占位脚本）
- [ ] 开发者工具「详情 → 本地代码」确认包体积，建议控制在 2MB 以内

### 2.4 自检命令

```bash

for f in $(git diff --name-only HEAD -- '*.js'); do node --check "$f" || echo "FAIL $f"; done
```

- [ ] 所有改动文件语法校验通过
- [ ] 全局搜索残留引用：确认无 `quickstartFunctions`、`example`、`cloudTipModal`

## 阶段三 · 上传并验证体验版

- [ ] 开发者工具右上角「上传」→ 填写版本号（如 `1.0.0`）与项目备注
- [ ] mp 后台 → 版本管理 → 确认出现**开发版本**
- [ ] 将开发版本设为**体验版**，生成体验二维码
- [ ] 添加体验成员（家人微信），添加后在「成员管理 → 体验成员」中生效

### 真机回归（必须用两个不同微信号，覆盖权限边界）

- [ ] 账号 A 创建家庭，生成邀请码
- [ ] 账号 B 用邀请码加入家庭
- [ ] 双方各记一笔，互相都能看到
- [ ] **首页「本月家庭开销」与「月度账单 → 本月总支出」金额一致** ← 本次修复的验证点
- [ ] 单月账目超过 100 笔时，两个金额仍然一致
- [ ] 普通成员尝试修改/删除他人账目 → 应被拒绝
- [ ] 转移管理员 → 原管理员变为普通成员
- [ ] 票据上传（相册 + 拍照两条路径）
- [ ] 导出 CSV，用 Excel 打开确认中文与列内容正常
- [ ] 创建备份 → 恢复备份
- [ ] **弱网/上传失败场景**：断网状态下上传票据，确认有明确错误提示而非静默成功

## 阶段四 · 提交审核

- [ ] mp 后台 → 版本管理 → 提交审核
- [ ] 填写**功能页面**（至少首页 + 账单 + 记账等核心页面）
- [ ] **准备测试账号** ← 最高发的驳回原因
  - 家庭账本必须让审核员能进到真实功能里
  - 方案：提供一个已创建家庭的测试微信号，或在补充说明中给出**固定邀请码 + 操作步骤**
  - 只给到 onboarding 页 = 大概率以「功能不完整」驳回
- [ ] 补充说明写清：产品定位、如何创建/加入家庭、数据仅家庭内可见
- [ ] 确认无未完成的占位内容、无「敬请期待」类空页面
- [ ] 审核时长通常 1–7 个工作日

### 常见驳回原因对照

| 驳回原因 | 对策 |
|---|---|
| 缺少隐私政策 / 未声明收集项 | 完成阶段一，后台声明与代码对齐 |
| 功能不完整、审核员看不到核心功能 | 提供测试账号或固定邀请码 + 说明 |
| 服务类目与实际功能不符 | 重新核对类目，必要时补资质 |
| 页面报错或白屏 | 确认云函数全部部署、索引已建 |
| 内容涉及未开放类目 | 调整功能范围或换主体 |
